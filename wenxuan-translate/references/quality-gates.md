# 8 大质量门（F1-F8）详细规则

> wenxuan-translate 的硬约束。100% 通过才交付。

---

## F1. 反虚构核查（Anti-Fabrication）

**核心**：译文中不能出现"原文无"的内容。

### 失败示例
- 原文没提"市场规模 10 亿"，译文不能编造这个数字
- 原文没提"创始人学历是哈佛"，译文不能补
- 原文写"some users"，译文不能具体化为"30% of users"
- 原文写"it might"，译文不能翻成"it is"（去掉了不确定性）

### 检测方式
- 事实核查 sub-agent 逐段对照原文
- 找出"加戏"段：原文说 A，译文说 A+B
- 找出"漏译"段：原文说 A+B，译文只说 A
- 找出"误译"段：原文说 A，译文说成 B

### 处理
- 发现加戏 → 重译该段，回到原文
- 发现漏译 → 补全
- 发现误译 → 修正

## F2. 术语一致性（Terminology Consistency）

**核心**：同一术语全文必须统一翻译。

### 失败示例
- 同一段里 "agents" 一会"代理"一会"智能体"
- 同一文档里 "inference" 一会"推理"一会"推断"
- 同一项目里 "framework" 一会"框架"一会"结构"

### 检测方式
- 事实核查 sub-agent 提取全文英文术语列表
- 检查每个术语的中文译法是否唯一
- 冲突的术语列入"术语表"统一规定

### 处理
- 第一次出现的术语 → 主 agent 决定译法
- 写入 `references/terminology-glossary.md`
- 后续出现 → 强制用统一译法
- 全文检索确保无冲突

### 常见术语建议译法
| 英文 | 中文 | 备注 |
|---|---|---|
| agents | 智能体 | AI 上下文 |
| inference | 推理 | AI 上下文 |
| framework | 框架 | 通用 |
| prompt | 提示词 | AI 上下文 |
| token | token | 不译（专业术语）|
| context window | 上下文窗口 | AI 上下文 |
| fine-tuning | 微调 | AI 上下文 |
| RAG | RAG | 不译（专业术语）|
| hallucination | 幻觉 | AI 上下文 |

## F3. 文化差异标注（Cultural Annotation）

**核心**：英文俗语/双关/文化梗要标注"原文 XXX，对应中文 XXX"。

### 失败示例
- "Bite the bullet" 直译为"咬子弹"未标注意译"硬着头皮"
- "Elephant in the room" 直译为"房间里的大象"未标注意译"显而易见却避而不谈的事"
- "Uncle Sam" 直译为"山姆大叔"未说明这是美国代称
- "Kleenex" 直译为"克林内克斯"未标注意译"面巾纸"

### 检测方式
- 事实核查 sub-agent 扫描所有俗语/双关/文化梗
- 判断是否需要中文注释
- 输出"文化差异标注表"

### 处理
- 译文里直译 + 括号注释原文喻意
- 或意译为中文对应表达 + 标注"原文为 XXX"
- 不要假装中文读者能理解所有英文文化梗

### 常见文化梗
| 英文 | 中文对应 | 标注方式 |
|---|---|---|
| Bite the bullet | 硬着头皮 | "Bite the bullet（直译：咬子弹）—— 硬着头皮" |
| Elephant in the room | 显而易见却避而不谈 | 必要时意译 + 标注 |
| Low-hanging fruit | 容易做的事 | 意译优先 |
| Red flag | 危险信号 | 直译 + 说明 |
| Out of the blue | 出乎意料 | 意译优先 |
| Pie in the sky | 空中楼阁 | 意译优先 |
| Crystal ball | 水晶球（预测）| 直译 + 说明 |

## F4. 翻译决策记录（Translation Decision Log）

**核心**：关键术语/难点翻法要记录为什么。

### 失败示例
- 关键术语翻译无任何说明
- 风格选择（意译/直译）无理由

### 处理
- 主 agent 翻译时自动记录关键决策
- 输出时汇总到"翻译说明"小节
- 格式：`<英文>` 翻为 `<中文译法>`，原因：`<...>`

### 示例
```
### 关键翻译决策
- "agents" 翻为"智能体"而非"代理"——本文为 AI 语境，用行业标准译法
- "the elephant in the room" 翻为"房间里的大象"——保留英文文化梗原文，括号注释中文对应"显而易见却避而不谈的事"
- "substack" 保留英文——平台名不译
```

## F5. 原文语气保留（Tone Preservation）

**核心**：英文讽刺/调侃/感叹，译文同等语气。

### 失败示例
- 原文讽刺，译文变严肃陈述
- 原文调侃，译文变平铺直叙
- 原文克制（短句/留白），译文变啰嗦

### 检测方式
- 人味 sub-agent 读原文，识别语气类型
- 比对译文语气是否一致
- 必要时修订

### 处理
- 语气类型：讽刺 / 克制 / 直白 / 调侃 / 正式 / 学术 / 口语
- 译文必须保留同一类型
- 必要时调整用词（如"这东西"比"该产品"更口语）

---

## F6. 长度自适应（Length Adaptation）

**核心**：中英文字数比按语义调整，不机械 1:1。

### 失败示例
- 一句英文硬翻成 3 句中文
- 一段英文翻成同长度的中文段落（说明没压缩）
- 中文一段太短（说明过度意译）

### 处理
- 英文 1000 词 → 中文 600-800 字（压缩 20-40%）
- 主 agent 翻译时按语义重新断句
- 不要机械追求"信息对齐"，要追求"等效传达"

---

## F7. 多轮自检（Multi-Round Self-Review）

**核心**：翻译完自己读一遍，找"翻译腔"重写。

### 失败示例
- 出现"值得注意的是""综上所述""不难发现"
- 出现"赋能""抓手""打造闭环"
- 出现"在当今...的时代"
- 出现"首先...其次...最后"工整对仗

### 处理
- 主 agent 翻译完成后必走一遍自检
- 命中上述词汇/句式 → 重写
- 详细 checklist 见 `references/renwei-prompt-snippet.md`

---

## F8. 人工复检高亮（Human Review Highlight）

**核心**：输出时高亮"建议人工复检"段落。

### 适用场景
- 长难句（>50 字的复杂句）
- 术语争议（同一术语 2 种译法都说得通）
- 语气把控不准（讽刺 vs 直白的边界）
- 文化梗 / 双关
- 涉及敏感内容（政治/宗教/种族）

### 处理
- 译文中以 `*【人工复检建议】*` 标记
- 在 Markdown 段落末尾注明复检建议（如"原文有 3 层意思，译文取了 1 层，建议复检是否完整"）
- 不强制重译，但提醒你重点看
