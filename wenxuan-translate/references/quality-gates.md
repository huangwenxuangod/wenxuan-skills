# 10 大质量门（F1-F10）详细规则

> wenxuan-translate 的硬约束。100% 通过才交付。

---

## F1. 反虚构核查（Anti-Fabrication）

**核心**：译文中不能出现"原文无"的内容。

### 失败示例
- 原文没提"市场规模 10 亿"，译文不能编造这个数字
- 原文没提"创始人学历是哈佛"，译文不能补
- 原文写"some users"，译文不能具体化为"30% of users"
- 原文写"it might"，译文不能翻成"it is"（去掉了不确定性）

### 检测方式
- 事实核查 sub-agent 逐段对照原文
- 找出"加戏"段：原文说 A，译文说 A+B
- 找出"漏译"段：原文说 A+B，译文只说 A
- 找出"误译"段：原文说 A，译文说成 B

### 处理
- 发现加戏 → 重译该段，回到原文
- 发现漏译 → 补全
- 发现误译 → 修正

## F2. 术语一致性（Terminology Consistency）

**核心**：同一术语全文必须统一翻译。

### 失败示例
- 同一段里 "agents" 一会"代理"一会"智能体"
- 同一文档里 "inference" 一会"推理"一会"推断"
- 同一项目里 "framework" 一会"框架"一会"结构"

### 检测方式
- 事实核查 sub-agent 提取全文英文术语列表
- 检查每个术语的中文译法是否唯一
- 冲突的术语列入"术语表"统一规定

### 处理
- 第一次出现的术语 → 主 agent 决定译法
- 写入 `references/terminology-glossary.md`
- 后续出现 → 强制用统一译法
- 全文检索确保无冲突

### 常见术语建议译法
| 英文 | 中文 | 备注 |
|---|---|---|
| agents | 智能体 | AI 上下文 |
| inference | 推理 | AI 上下文 |
| framework | 框架 | 通用 |
| prompt | 提示词 | AI 上下文 |
| token | token | 不译（专业术语）|
| context window | 上下文窗口 | AI 上下文 |
| fine-tuning | 微调 | AI 上下文 |
| RAG | RAG | 不译（专业术语）|
| hallucination | 幻觉 | AI 上下文 |

## F3. 文化处理 5 步决策树（Cultural Handling Decision Tree）

**核心**：英文俗语/双关/文化梗不能简单直译，要走 5 步决策树决定处理方式。

### 5 步决策树

#### Step 1: 识别（Identify）

主 agent + 人味 sub-agent 并行扫描原文，识别所有疑似文化梗：

| 类别 | 例子 | 识别信号 |
|---|---|---|
| **习语/俗语** | bite the bullet, elephant in the room, low-hanging fruit | 4 字以上固定搭配、有隐喻 |
| **典故/神话** | Achilles' heel, Midas touch, Pandora's box | 出现希腊/罗马/圣经人物名 |
| **流行梗/Meme** | this is fine, distracted boyfriend, Galaxy Brain | 出现年份/平台/视频相关词 |
| **文化符号** | Uncle Sam, Wall Street, Hollywood, Silicon Valley | 出现国家/地区/产业专有名词 |
| **历史事件** | 9/11, 2008 financial crisis, Black Monday | 出现具体日期+事件 |
| **节日习俗** | Thanksgiving, Black Friday, April Fools' Day | 出现节日名 |
| **法律/政治术语** | checks and balances, gerrymandering, filibuster | 出现美国政治/法律专属概念 |

#### Step 2: 搜补（Search & Augment）

**关键**：识别到文化梗后，**必须用搜索补齐上下文**（v1.1 新增能力）：

| 搜索目标 | 工具 | 输出 |
|---|---|---|
| 梗的来源 / 出处 | WebSearch | 1-2 句来源说明 |
| 梗的隐喻含义 | WebSearch | 1-2 句解释 |
| 当前是否还流行 | WebSearch | "已过时" / "仍在用" / "meme 化" |
| 中文社区对应表达 | WebSearch | 1-2 个对应中文梗/表达 |

**5 步搜索法**：
1. `WebSearch "<英文梗> origin meaning"` → 找定义+来源
2. `WebSearch "<英文梗> 中文翻译 解释"` → 找中文社区译法
3. `WebSearch "<英文梗> 2026"` → 看是否还流行
4. `WebSearch "<英文梗> meme"` → 看是否 meme 化
5. 必要时 WebFetch 维基百科 / 知乎 / Reddit 详情页

#### Step 3: 选路（Choose Path）

拿到搜索结果后，从 4 条路里选 1 条：

| 路径 | 适用 | 处理 |
|---|---|---|
| **A. 直译保留** | 中文读者能理解（"象牙塔"）| 直译 + 必要时加 1 句简注 |
| **B. 意译替换** | 中文有对应表达（elephant in the room → 避而不谈的事）| 直接意译，**可在脚注标"原文为 XXX"** |
| **C. 加注保留** | 直译不达意但有文化价值（Pandora's box → 潘多拉盒子）| 直译 + 括注喻意 |
| **D. 双语对照** | 学术/原教旨场景 | 保留英文 + 中文解释 |

**默认选 B**，只在以下情况选 C：
- 原文作者**明显想用英文文化符号**（如分析美国政治的专栏）
- 文化梗在中文里有**完全对等**的接受度（很少见）

#### Step 4: 标注（Annotate）

| 标注方式 | 格式 | 何时用 |
|---|---|---|
| **行内简注** | `Pandora's box（潘多拉盒子，指带来灾祸的礼物）` | 默认 |
| **脚注详注** | `...打开潘多拉盒子[^1]` + 末尾 `[^1]: Pandora's box：希腊神话中宙斯给潘多拉的盒子，象征带来灾祸的礼物` | 长篇/学术 |
| **不标注** | 直接意译为"打开灾祸之门" | 中文有完全对等表达时 |

#### Step 5: 复检（Re-check）

事实核查 sub-agent 拿到标注后，过一遍：
- 是否漏标注？
- 标注内容是否准确（基于搜索结果）？
- 中文译法是否传达了原文的语气？
- 是否需要补 F8 人工复检高亮？

### 失败示例（重写版）

| ❌ 错误处理 | ✓ 正确处理 |
|---|---|
| "Bite the bullet" 直译为"咬子弹"未标注 | "硬着头皮（原文 bite the bullet，直译'咬子弹'，指忍痛做难事）" |
| "Elephant in the room" 直译为"房间里的大象"未说明 | "房间里的大象（指显而易见却避而不谈的事）" |
| "Uncle Sam" 直译为"山姆大叔"未说明 | "山姆大叔（美国的拟人化代称，类似中文的'老大哥'）" |
| "This is fine" 不查直接翻 | **先搜**：原出 2013 年 KC Green 漫画 "This is Fine"，meme 化指"明知有问题却假装没事" → 译为"装作没事" + 加注"原出 2013 年 KC Green 漫画 'This is Fine'，表达对问题视而不见" |

### 常见文化梗处理速查表

| 英文 | 中文对应 | 推荐路径 | 备注 |
|---|---|---|---|
| Bite the bullet | 硬着头皮 | B 意译 | 必要时加"原文 bite the bullet" |

## F4. 翻译决策记录（Translation Decision Log）

**核心**：关键术语/难点翻法要记录为什么。

### 失败示例
- 关键术语翻译无任何说明
- 风格选择（意译/直译）无理由

### 处理
- 主 agent 翻译时自动记录关键决策
- 输出时汇总到"翻译说明"小节
- 格式：`<英文>` 翻为 `<中文译法>`，原因：`<...>`

### 示例
```
### 关键翻译决策
- "agents" 翻为"智能体"而非"代理"——本文为 AI 语境，用行业标准译法
- "the elephant in the room" 翻为"房间里的大象"——保留英文文化梗原文，括号注释中文对应"显而易见却避而不谈的事"
- "substack" 保留英文——平台名不译
```

## F5. 原文语气保留（Tone Preservation）

**核心**：英文讽刺/调侃/感叹，译文同等语气。

### 失败示例
- 原文讽刺，译文变严肃陈述
- 原文调侃，译文变平铺直叙
- 原文克制（短句/留白），译文变啰嗦

### 检测方式
- 人味 sub-agent 读原文，识别语气类型
- 比对译文语气是否一致
- 必要时修订

### 处理
- 语气类型：讽刺 / 克制 / 直白 / 调侃 / 正式 / 学术 / 口语
- 译文必须保留同一类型
- 必要时调整用词（如"这东西"比"该产品"更口语）

### 声音校准 4 维对齐（v1.1 新增）

光识别语气类型还不够，要**量化对齐**到 4 个维度：

| 维度 | 含义 | 测量方法 | 偏差容忍 |
|---|---|---|---|
| **句长** | 平均句字数 | 中文译文平均句长（字/句）vs 原文平均句长（词/句）比值 | 0.7-1.3 |
| **标点密度** | 感叹号/问号/破折号使用频率 | 中文译文标点密度 vs 原文标点密度 | ±30% |
| **人称** | 第一/第二/第三人称出现频率 | 中文译文人称分布 vs 原文人称分布 | 偏差 ≤ 2 次/千字 |
| **正式度** | 词汇口语/书面语比例 | 中文译文"这东西/你"等口语词占比 vs 原文"this thing/you"占比 | ±20% |

### 校准流程

1. **测量原文**：先算出原文的 4 维基线（句长/标点/人称/正式度）
2. **测量译文**：再算译文的 4 维数值
3. **比对差异**：4 维逐项比对，看哪一维偏差最大
4. **定向修订**：只修偏差 > 容忍度的那一维，**不要全盘推翻**
5. **复测确认**：修订后重测，确认 4 维都落入容忍区间

### 校准示例

> 原文（克制型）："I tried. It failed. I moved on."（3 句，平均 4 词/句，无标点，第三人称，正式度低）

| 维度 | 原文 | 译文 A（错）| 译文 B（对）|
|---|---|---|---|
| 句长 | 4 词/句 | 28 字/句（啰嗦）| 5 字/句 |
| 标点 | 无 | 大量逗号、句号 | 3 个句号 |
| 人称 | 第三人称 | 第一人称"我" | 第三人称 |
| 正式度 | 低 | 高（"该次尝试未能成功"）| 低（"我试了。挂了。过去了。"）|

**译文 A** 4 维全错——典型的"加戏"翻译腔。
**译文 B** 4 维对齐——保留了原文的克制感。

## F6. 长度自适应（Length Adaptation）

**核心**：中英文字数比按语义调整，不机械 1:1。

### 失败示例
- 一句英文硬翻成 3 句中文
- 一段英文翻成同长度的中文段落（说明没压缩）
- 中文一段太短（说明过度意译）

### 处理
- 英文 1000 词 → 中文 600-800 字（压缩 20-40%）
- 主 agent 翻译时按语义重新断句
- 不要机械追求"信息对齐"，要追求"等效传达"

---

## F7. 多轮自检（Multi-Round Self-Review）

**核心**：翻译完自己读一遍，找"翻译腔"重写。

### 失败示例
- 出现"值得注意的是""综上所述""不难发现"
- 出现"赋能""抓手""打造闭环"
- 出现"在当今...的时代"
- 出现"首先...其次...最后"工整对仗

### 处理
- 主 agent 翻译完成后必走一遍自检
- 命中上述词汇/句式 → 重写
- 详细 checklist 见 `references/humanlize-prompt-snippet.md`

---

## F8. 人工复检高亮（Human Review Highlight）

**核心**：输出时高亮"建议人工复检"段落。

### 适用场景
- 长难句（>50 字的复杂句）
- 术语争议（同一术语 2 种译法都说得通）
- 语气把控不准（讽刺 vs 直白的边界）
- 文化梗 / 双关
- 涉及敏感内容（政治/宗教/种族）

### 处理
- 译文中以 `*【人工复检建议】*` 标记
- 在 Markdown 段落末尾注明复检建议（如"原文有 3 层意思，译文取了 1 层，建议复检是否完整"）
- 不强制重译，但提醒你重点看

## F9. 反向校验（Back-Translation Check）

**核心**：关键段落做中→英 back-translation，看反向译文是否还原原文含义。

### 适用场景

不是所有段落都要做反向校验。只对**关键段落**做：

| 段落类型 | 是否做反向校验 | 原因 |
|---|---|---|
| **核心论点**（文章中心思想）| 必做 | 一旦走样，全篇塌方 |
| **数据/数字段**（带具体数字、百分比、年份）| 必做 | 数字易翻错 |
| **长难句**（>50 字复杂句）| 必做 | 易丢失逻辑层次 |
| **术语争议段**（F2 标记过的术语）| 必做 | 译法可能有偏差 |
| **文化梗段**（F3 标记过的）| 必做 | 意译易走样 |
| **故事/案例段** | 选做 | 影响阅读体验但不影响中心思想 |
| **普通论述段** | 不做 | 投入产出比低 |

### 反向校验流程

```
原文（英） → 主 agent 译为中文 → 反向 sub-agent 译回英文
                ↓
          比对反向英文与原文
                ↓
       关键信息一致？→ 通过
       关键信息走样？→ 修订中文译文，重做
```

#### Step 1: 标记关键段落
- 主 agent 翻译时自动识别"关键段落"（按上表）
- 段落前加标记：`【F9 必校】`

#### Step 2: 派反向 sub-agent
- 用单独的 sub-agent 拿中文译文，**不参考原文**，**英译回英文**
- 强制要求 sub-agent "完全直译，不要润色"

#### Step 3: 逐项比对
事实核查 sub-agent 拿到原文 + 反向英文，逐项比对：

| 比对项 | 允许偏差 | 严重偏差（需重译）|
|---|---|---|
| **核心事实** | 表达方式可不同 | 数字/人名/时间/地点错误 |
| **逻辑关系** | 顺序可调整 | 因果/转折/并列关系颠倒 |
| **语气类型** | 强度可微调 | 讽刺变严肃、调侃变陈述 |
| **细节完整度** | 可省略重复表述 | 关键限定词/范围词丢失 |
| **数据/数字** | 必须 100% 一致 | 任何数字偏差 |

#### Step 4: 输出"反向校验报告"

```markdown
### F9 反向校验报告

| 段落 | 关键信息 | 偏差类型 | 严重度 | 处理 |
|---|---|---|---|---|
| L23-L25 | 数字 30% → 反向译文 30% | 一致 | 无 | 通过 |
| L47-L50 | 因果关系 A→B → 反向译文 A→C | 逻辑颠倒 | 高 | 重译 |
| L72 | "讽刺"语气 → 反向译文"陈述" | 语气偏移 | 中 | 修订 |
```

#### Step 5: 修订 → 复验
- 高严重度偏差 → 必修订 → 重做反向校验
- 中严重度偏差 → 修订 → 复验
- 低严重度偏差 → 记录到 F8 人工复检高亮

### 反向校验的边界

| 能抓到 | 抓不到 |
|---|---|
| 数字/事实错误 | 中文本身的语病 |
| 逻辑关系走样 | 译文的"翻译腔"（F7 抓）|
| 关键限定词丢失 | 风格不到位（人味 sub 抓）|
| 语气严重偏移 | 细微的语气差异 |
| 关键词译错 | 段落结构问题（F6 抓）|

### 实用反向校验 prompt

```
你是反向校验 sub-agent。任务：

1. 拿到中文译文：<中文段落>
2. 拿不到原文（不要看原文）
3. 把它**直译**回英文（不要润色、不要补意思）
4. 输出：
   - 反向英文：<你的译文>
   - 不确定的点：<有哪些词/句你不确定怎么翻>

要求：300 字以内，**不要追求文采**。
```

### 通过标准

- 所有"必做"反向校验段落：**关键信息一致率 = 100%**
- 高严重度偏差：**0 个**
- 中严重度偏差：**0 个**
- 低严重度偏差：≤ 2 个/篇（且已标 F8）

任一不通过 → 打回主 agent 重译该段 → 重做反向校验。

## F10. 图片保留门（Image Preservation Gate）

**核心**：源文档里的所有图片（`<img>` / Markdown `![alt](url)` / Newsletter 配图 / 推文截图）**必须 1:1 复制到译文里**，一张都不能丢。

### 为什么是硬门

- 译文读者**看不到原推文** —— 推文配图往往是核心信息载体（截图、流程图、数据可视化）
- 主 agent 翻译时极易"合并段落顺手删图" —— 看上去不重要的配图，往往是文章的视觉骨架
- 漏图会导致：① 上下文断裂 ② 关键信息缺失（截图里的产品名/数字） ③ 阅读体验断裂

### 强制规则

1. **翻译开始前** → 扫描源文档，统计 `!\[.*\]\(.*\)` 和 `<img>` 数量，记为 `IMG_SRC_COUNT`
2. **翻译过程中** → 遇到图片链接，**直接复制到译文对应位置**（不下载、不丢弃、不加图说）
3. **翻译结束后** → 扫描译文 MD，统计图片数量，记为 `IMG_TGT_COUNT`
4. **判定** → `IMG_TGT_COUNT >= IMG_SRC_COUNT`（允许"图说翻译"但不允许"图丢失"）

### 失败处理

- `IMG_TGT_COUNT < IMG_SRC_COUNT` → **打回重译**
- 缺失图片的位置：回到源文档，定位图片所在段落，把图片链接按位置补回译文

### 实战案例（2026-06-15）

源 MD `Clippings/How to Master Claude (FULL GUIDE) MD.md` 共 **14 张**图片（X 推文截图 pbs.twimg.com 域名）。

主 agent 翻译后译文 MD：**0 张**图片——F10 门未启用前，14 张图全部丢失。

修复：手动按源 MD 位置补回 14 张图，MD 视觉信息完整。

**教训**：图片保留不是"流程备注"，是**硬门**。F10 必须跑。

### 边界情况

| 场景 | 处理 |
|---|---|
| 纯装饰性图标 | 仍保留（视觉一致性） |
| 重复图片（同一 URL 出现多次） | 都保留 |
| 外链图 404 | 在图下用文字描述"原图已失效" + 简述内容 |
| 图说含原文 | 图说翻译，图保留 |
| 视频/GIF | 保留链接，MD 阅读器自动渲染预览 |
| 本地相对路径图片 | MD 阅读器（Obsidian/Typora）自动定位 |

## 质量门通过标准

**所有 F1-F10 必须 100% 通过**才能交付。

| 质量门 | 通过判定 | 失败处理 |
|---|---|---|
| F1 反虚构 | 加戏段数 = 0 | 重译该段 |
| F2 术语一致 | 冲突术语数 = 0 | 统一术语表 |
| F3 文化标注 | 缺失标注 = 0 | 补标注 |
| F4 决策记录 | 关键决策覆盖 100% | 补记录 |
| F5 语气保留 | 声音校准 4 维偏差 ≤ 容忍度 | 定向修订 |
| F6 长度适应 | 字数比 0.6-0.8 | 重新断句 |
| F7 自检 | AI 味 3 维合计 ≤ 2 分 | 重写 |
| F8 人工高亮 | 建议段落标注 = 100% | 补标注 |
| F9 反向校验 | 关键信息一致率 = 100% | 重译该段 |
| F10 图片保留 | 译文图片数 ≥ 源图片数 | 按位置补图 |

任一不通过 → 打回重译 → 再次走全部质量门 → 直到通过。
