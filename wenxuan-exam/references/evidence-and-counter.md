# 证据与反方

这份文件解决一件事：**搜到的信息很多，但理解仍然片面。**

## 证据卡格式

每条关键主张一张卡。卡的主体是原文摘录，不是 AI 的概括。

```markdown
### 卡 E3 · <一句话主张>

- 主张：<用一句可被反驳的话写>
- 原文摘录：「<原句>」
- 出处：<作者/机构>｜<标题>｜<发布日期>｜<URL>｜访问 <YYYY-MM-DD>
- 来源类型：官方 / 独立第三方 / 社区 / 本人实测
- 原始语境：<这句话是在什么条件下说的：产品发布会？压力测试？客户访谈？>
- 比较条件：硬件 < >｜版本 < >｜任务 < >｜样本 < >｜时间 < >
- 反向检索：已搜 `<>`，结果 <有相反结果 / 未找到相反结果>
- 冲突材料：<若有，列出另一侧原文与出处；无则写"未找到">
- 我的判断：[待你填写] 已确认 / 有条件成立 / 证据不足
- 我还有什么不知道：[待你填写]
```

写卡禁区：不要在卡里写"说明""因此可以看出""这意味着"。摘录和整理之间必须有一条明确的线。

## 怎么判断"证据够不够"

三个门槛，全过才算够：

1. **可追溯**：能点开到原文，且原文里确实有这句。
2. **可比**：用来做比较的两组数据，条件一致或差异被记录。
3. **可反驳**：能说清楚"什么结果出现时，这条主张就是错的"。

过不了第三条的，是信念不是证据。

## 反方检索的四条路径

多数人的研究是：看到观点 -> 搜支持它的文章 -> 发现很多人赞同 -> 得出结论。反过来做：

1. **找迁移叙事**：`X we moved away from` / `X 为什么放弃` / `X 迁移到 Y`。
2. **找失败现场**：GitHub Issues 的 closed 与 stale、生产事故复盘、费率超支的吐槽。
3. **找竞争方的技术论证**：竞品团队写的对比文，虽然立场鲜明，但常能指出真实弱点。
4. **找审稿意见与复现失败**：论文的 rebuttal、复现帖、"我们复现不出来"。

最强的反方不是骂人的帖子，而是**同条件下做出相反结果的人**。

## 七种偏误检查（每张卡过一遍）

| 偏误 | 长什么样 | 检查动作 |
|---|---|---|
| 确认偏误 | 只搜了支持自己的词 | 反方检索跑了吗？ |
| 幸存者偏差 | 只看到成功案例 | 失败的人还说话吗？有没有沉默样本？ |
| 单源传播 | 三个媒体引同一篇通稿 | 追到最上游，是否只有一个原始出处？ |
| 营销混入技术 | 把官网的一句话当机制 | 有实现细节或独立复现吗？ |
| 相关性当因果 | "用了 X 的公司都增长了" | 有没有第三变量？对照组是谁？ |
| 基准测试幻觉 | 榜上分数高就代表好用 | 测试任务和你真实任务差多远？ |
| 时间错位 | 用一年前的数据谈现在 | 查发布日期与最新版本 |

## 冲突处理

同一事实出现相反材料时，**不要平均、不要折中**。做三件事：

1. 并列原文，标注双方的条件差异（谁的样本更大、版本更新、任务更接近真实场景）。
2. 写清"如果 A 对，结论是什么；如果 B 对，结论是什么"。
3. 交给用户在 03 分析笔记里做裁决，并写进"未知清单"。

AI 只负责把两侧摆平，裁决权在用户。
