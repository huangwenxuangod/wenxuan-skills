# wenxuan-research — 行业认知研究引擎

## 核心理念

**不是出报告，是建认知。** 一篇文章读了三天记不住，但一份"行业数据库"可以用三年。

进入新行业最大的坑不是信息太少，而是**信息太散**。搜了 200 个链接、收藏了 50 个公众号，三天后脑子还是浆糊。

> **「不是你的搜索能力不行，是你的存储结构没建对。」**

wenxuan-research 的目标：**从一次研究里沉淀出一个可复用的行业操作系统**，下次进入相邻行业时可以调用。

## 与 wenxuan-learn 的边界

| 维度 | wenxuan-learn | wenxuan-research |
|------|---------------|------------------|
| 目标 | 写一篇文章 | 吃透一个行业 |
| 输出 | 选题学习包.md | 行业报告.md + Obsidian 目录树 |
| 时间跨度 | 一两天 | 行业可复用 1-3 年 |
| 落点 | 文章用法 | 数据库/地图/机会 |
| 强约束 | 必接 anti-pua 逼输出 | **不接 anti-pua**（研究是慢活，不是写稿） |
| 决策方向 | 选定一个选题深挖 | 全景扫描，呈现机会地图 |

**触发分流**：
- "我想写一篇关于 XX" → wenxuan-learn
- "我想了解一下 XX 行业" / "帮我研究一下 XX 市场" / "/wenxuan-research XX" → wenxuan-research
- 给我一份 arXiv 论文 → wenxuan-paper
- 给我一个 PDF 但不知道是不是论文 → 优先 wenxuan-paper（学术识别度高）

## 12 个核心思维模型（贯穿 4 步 + 增量更新）

| # | 模型 | 一句话 | 步骤 |
|---|------|--------|------|
| 1 | **结构 > 信息** | 目录树定下来，信息才有位置 | 1 |
| 2 | **先建库后看细节** | 不读完就归档，边读边建 | 1 |
| 3 | **拆导航 = 拆大脑** | 网站 nav 决定用户看到什么、买什么 | 2 |
| 4 | **拆 Collection > 拆 Product** | Collection 才是成交路径 | 2 |
| 5 | **拆 Tag = 拆搜索** | 标签体系告诉你用户和搜索引擎怎么理解产品 | 2 |
| 6 | **拆 Blog = 拆 SEO 流量** | 头部品牌的 Blog 结构是行业流量集中地 | 2 |
| 7 | **100 个账号 > 1 个账号** | 看一个猜运气，看 100 个看规律 | 3 |
| 8 | **重复爆款 > 偶然爆款** | 一次爆是运气，十次爆是规律 | 3 |
| 9 | **内容五分法** | 曝光/涨粉/收藏/转化/人设 | 3 |
| 10 | **网络 > 树** | 真正的高手看行业是看连接关系，不是层级 | 4 |
| 11 | **数据库解决存储，地图解决理解** | 大量卡片 = 收藏夹焦虑；地图 = 操作系统 | 4 |
| 12 | **机会 = 节点缺口** | 行业地图里没人占的节点，就是机会 | 4 |

## 事实核查（复用 wenxuan-learn 机制）

直接复用 wenxuan-learn 的「事实核查 + 剔除清单」机制——核查对象（数据/引用/产品/人物/事件）、核查标准、强制移除规则全部一致。

输出文档末尾必须有「⚠️ 事实核查剔除清单」段。行业研究里品牌名、产品规格、数据出处最容易出错，剔除清单尤其要严格。

## 4 步流程 + 增量更新

### 第 1 步：建立行业数据库（先建库后看细节）

**核心动作**：让 Codex 先输出**完整的行业目录结构**，再为每个目录建 Markdown 文件。所有内容适合导入 Obsidian。

#### 1.1 一级目录（强制 8 个）

```
<行业名>-Industry/
├── Brands/                # 品牌数据库
├── Products/              # 产品数据库
├── Pain-Points/           # 用户痛点数据库
├── Keywords/              # 关键词数据库
├── Content-Channels/      # 流量获取渠道
├── Competitors/           # 竞品数据库
├── Business-Models/       # 商业模式
├── Regulations/           # 监管/合规
├── Trends/                # 趋势
└── Opportunities/         # 机会
```

#### 1.2 Brands/ 数据库

让 Codex 统计 **Top 100 品牌**（或行业实际数量），每个品牌一个 .md：

```markdown
# [品牌名]
- 官网：[URL]
- 主要产品：[产品类别]
- 价格区间：[区间]
- 销售渠道：[渠道列表]
- 估计规模：[年营收/估值/用户量]
- 核心卖点：[一句话]
- 创始人背景：[履历]
- 社媒账号：[链接列表]
```

#### 1.3 Products/ 数据库

按市场规模排序的产品类型：

```
Products/
├── [类型1]/
│   ├── 主要成分
│   ├── 用户评价
│   ├── 优点
│   ├── 缺点
│   ├── 爆款品牌
│   └── 市场规模
├── [类型2]/
└── ...
```

#### 1.4 Pain-Points/ 数据库（价值最高）

直接整理 **Reddit / Quora / 知乎 / 论坛** 真实用户讨论：
- 高频抱怨
- 高频需求
- 高频问题
- 用户目标

#### 1.5 Keywords/ 数据库

分 4 类整理：
- Google 关键词
- Amazon 关键词（如适用）
- Reddit / 社区关键词
- 平台原生关键词（YouTube / TikTok / 小红书）

按搜索意图分类：
- Commercial（购买意图）
- Informational（信息查询）
- Comparison（对比）
- Review（评测）
- Buying Intent（强购买）

#### 1.6 Content-Channels/ 数据库

按平台分类的**头部账号**：
- YouTube 头部频道
- TikTok 头部账号
- Instagram 头部账号
- X 头部账号
- Newsletter
- 小红书 / 公众号 / B 站（如适用）

每个平台 50-100 个账号，输出：账号名、粉丝数、更新频率、主要方向、变现模式。

**完成后**：
```
行业数据库
├── 品牌数据库
├── 产品数据库
├── 用户数据库
├── 关键词数据库
└── 内容数据库
```

### 第 2 步：拆解同行怎么赚钱（先拆大脑后找产品）

**核心动作**：从同行已经交过的学费里学东西。

#### 2.1 建立竞品数据库

假设 Shopify 行业：选 10 个头部品牌 → 每个 .md 一个完整拆解。

#### 2.2 拆导航栏（= 拆大脑）

让 Codex 分析竞品网站，输出：
1. 导航结构（一级/二级菜单）
2. 产品分类
3. Collection 结构
4. Product Tag 结构
5. Footer 结构
6. Blog 结构
7. SEO 结构（H1/H2/meta/URL 模式）
8. Landing Page 结构

输出成 `competitor-analysis-[品牌名].md`。

**思维模型 #3**：导航栏 = 老板的大脑。决定用户进站后第一步看到什么、第二步看到什么、第三步买什么。

#### 2.3 拆 Collection（比 Product 重要）

- Best Sellers（利润品）
- New Arrival（流量品）
- Under $X（转化品）
- Gift For Her/Him（场景品）

**思维模型 #4**：Collection 才是成交路径。

#### 2.4 拆 Product Tag（= 拆搜索）

分析 1000 个产品的 Tag，归纳出**整个行业的标签体系**。Tag 同时告诉：用户怎么搜、搜索引擎怎么理解、推荐系统怎么工作。

#### 2.5 拆 SEO 结构

- Top 10 [关键词]
- Best [关键词]
- [关键词] Review
- [关键词 A] vs [关键词 B]
- How To [关键词]

头部品牌抢的话题 = 行业流量集中地。

#### 2.6 拆 Blog 内容

抓最近一年的 Blog，统计：
- 浏览量最高
- 更新频率最高
- 出现次数最高（被内链最多）
- 形成 `blog-analysis.md`

**思维模型 #6**：Blog 藏着行业最大流量来源。赚钱的品牌 Blog 都不是随便写的。

#### 2.7 拆社交媒体

按平台分：
- 曝光型
- 涨粉型
- 收藏型
- 转化型
- 人设型

**最终**：
```
Competitor Database
├── Website Structure
├── Product Structure
├── Collection Structure
├── Tag Structure
├── SEO Structure
├── Blog Structure
└── Social Structure
```

### 第 3 步：研究行业内容生态

**核心动作**：在今天这个时代，**内容本身就是生产资料**。流量决定订单，内容决定流量。

#### 3.1 研究 100 个账号，不是 1 个

**思维模型 #7**：100 个账号 > 1 个账号。

1 个账号看了半年也找不出规律。100 个账号看一周就能看见模式。

#### 3.2 找出流量收割机

分析最近 90 天内容：
- 点赞最高 Top 100
- 评论最高 Top 100
- 转发最高 Top 100
- 播放最高 Top 100

#### 3.3 给内容分五类（思维模型 #9）

| 类型 | 特点 | 例子 |
|------|------|------|
| **曝光型** | 观点强、争议大、易传播 | "中文 AI 圈 80% 都是二手信息" |
| **涨粉型** | 资源型、推荐型、账号型 | "10 个值得关注的 AI 频道" |
| **收藏型** | SOP、步骤、模板、工作流 | "如何用 Codex 研究一个行业" |
| **转化型** | 展示结果、案例、收益 | "我用 AI 做了个网站，30 天 10 万访问" |
| **人设型** | 故事、经历、踩坑、复盘 | "我运营推特 4 个月，880 万曝光" |

#### 3.4 找出重复爆款（思维模型 #8）

**思维模型 #8**：**重复爆款 > 偶然爆款**。

一次爆 = 运气；十次爆 = 规律。

统计：
- 哪些选题反复爆
- 哪些结构反复爆
- 哪些标题反复爆
- 哪些内容类型反复爆

#### 3.5 建立自己的内容数据库

```
Content System
├── Exposure/
├── Growth/
├── Save/
├── Conversion/
└── Personal-Brand/
```

**最终**：
- 不是娱乐，是数据库
- 不是焦虑，是规律
- 不是消费，是研究

### 第 4 步：建立行业知识地图

**核心动作**：把碎片变网络。

#### 4.1 数据库解决存储，地图解决理解

**思维模型 #10/11**：大量卡片 = 收藏夹焦虑；地图 = 操作系统。

#### 4.2 拆一级地图

让 Codex 输出 Markdown 树状结构：
```
[行业名]
├── 一级目录
│   ├── 二级目录
│   │   ├── 三级目录
```

#### 4.3 拆到第三层

每条线都拆到三个层级为止。

#### 4.4 给每个节点建知识卡片

```
Knowledge Map
├── [节点1]/
│   ├── overview.md
│   ├── companies.md
│   ├── tools.md
│   ├── trends.md
│   └── opportunities.md
├── [节点2]/
└── ...
```

#### 4.5 建立行业之间的连接

**思维模型 #10**：网络 > 树。高手的认知不是层级，是连接。

```
Model → Agent → Workflow → Enterprise
GPU → Training → Model → Application → Revenue
```

#### 4.6 机会地图（最高价值）

让 Codex 分析：
- 哪些领域竞争最激烈
- 哪些领域增长最快
- 哪些领域创业机会最大
- 哪些领域内容供给不足

输出：
```
Opportunities/
├── [机会1]/
├── [机会2]/
└── ...
```

**思维模型 #12**：机会 = 节点缺口。行业地图里没人占的节点 = 机会。

## 增量更新（每次跑自动触发）

> 替代原"第 5 步·持续监控"。监控需要 RSS/cron 等外部基础设施；增量更新**只在 wenxuan-research 跑完后自动执行**，把每次研究沉淀为对知识图谱的扩充。

### 触发时机

**每次 `wenxuan-research` 跑完 4 步后自动进入本阶段**，无需用户额外指令。

### 三个动作

#### 1. 信源查重与扩充

将本次研究中**新发现**的优质信源与 `references/source-quality.md` 对比：

| 结果 | 处理 |
|------|------|
| 完全相同 | 跳过 |
| 同名不同物 | 进事实核查剔除清单（"三件套辨认失败"），不进表 |
| 真正新信源 | 按三级分级（A/B/C）追加到 `references/source-quality.md` 末尾 |
| 现有信源被验证为高质量 | 标 ★ 升级（如 C → B） |
| 现有信源被证伪 | 标 ✗ 降级或从表移除 |

#### 2. 知识图谱增量更新

把本次发现的**新节点 / 新连接**追加到行业地图：

- 在 `Knowledge-Map/<行业>-Knowledge-Map.md` 末尾追加**新发现的子领域**
- 更新 `Opportunities/` 目录：发现新机会节点 → 新建子目录
- 已有节点的子卡片（`companies.md` / `tools.md` / `trends.md`）：**增量更新而不覆盖**

#### 3. 沉淀到项目仓库

把增量结果写到 `内容/行业/<行业名>/increments/<日期>-increment.md`：

```markdown
# <行业名> 增量更新 · <YYYY-MM-DD>

## 本次新增信源
- **<信源名>** (A/B/C) — <一句话说明>

## 本次知识图谱变化
- 新增节点：[节点名]
- 新增连接：[节点A] → [节点B]
- 节点升级：[节点] (旧关系) → (新关系)

## 本次机会变化
- 新发现：[机会名] — [一句话]

## 累计统计
- 信源总数：N (A: x / B: y / C: z)
- 知识节点：N
- 机会池：N
- 距上次更新：N 天
```

### 效果

每跑一次 wenxuan-research，**知识图谱就丰富一层**：
- 信源从 N 个 → N+1 个（A/B/C 同步刷新）
- 知识节点从 M 个 → M+k 个
- 机会池从 P 个 → P+j 个
- 行业数据库从 30% → 35% → 50% → 70% 持续增长

**不需要 cron / RSS / 周报**。是"研究驱动"而非"订阅驱动"。

## 输出物（双轨）

### 主输出：`行业认知报告.md`

一份**可读的总报告**，包含：
- 速览（一句话定义行业核心冲突）
- 行业一句话总结
- 4 步执行摘要 + 增量更新摘要
- 关键发现（思维模型应用后的洞察）
- ⚠️ 事实核查剔除清单
- 下一步建议

### 副输出：Obsidian 目录树

完整的 `<行业名>-Industry/` 目录树，所有 .md 文件可导入 Obsidian 长期使用。

## 搜索规则

- **来源比例**：80% 英文 + 20% 中文（除非是中文行业）
- **质量门槛**：A 类一手信源为主（详见 `references/source-quality.md`）
- **轮数**：至少 30 轮（行业研究 > 选题研究）
- **策略**：发散 → 挖根 → 找关键词 → 再搜索 → 直到行业地图完整
- **事实核查**：必走，未通过的写剔除清单

> **信源分级**：A 类（官方/GitHub/论文/产品本体，必查）→ B 类（权威媒体/大佬博客，需交叉）→ C 类（社区/社媒，只作辅证）。详见 `references/source-quality.md`。

## 触发方式

1. `/wenxuan-research XX` — 主动触发
2. 用户说"我想了解一下 XX 行业" / "帮我研究一下 XX 市场" — 自动触发
3. 用户说"进入新行业，怎么快速了解" — 自动触发

**不触发**：
- "我想写一篇关于 XX"（用 wenxuan-learn）
- 给我 PDF 论文（用 wenxuan-paper）
- "整理一下会议记录"（不在任何 skill 范围）
